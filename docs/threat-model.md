# Threat Model — Audit Compliance Module

| Field    | Value                                    |
|----------|------------------------------------------|
| Module   | auditcompliance v17.0.0-alpha            |
| Date     | 21-02-2026                               |
| Status   | Draft                                    |
| Audience | Developers, Security Officers            |

- Platform: FreePBX 17 / pbxACT
- Methodology: STRIDE + OWASP Top 10 mapping

---

## 1. System Context

```
[Admin Browser] --HTTPS--> [FreePBX Web GUI] --TLS--> [Remote Audit DB]
                                |
                  [Audit Module (BMO hooks)]
                                |
                  [FreePBX Internal DB (config)]
```

### Trust Boundaries

1. **Browser ↔ FreePBX**: HTTPS with FreePBX session management
2. **FreePBX ↔ Audit DB**: TLS-required PDO connection, dedicated least-privilege role
3. **Admin ↔ Audit Data**: Read-only access through module GUI, no direct DB access

### Assets

| Asset | Classification | Protection |
|-------|---------------|------------|
| Audit event records | Compliance-critical | Append-only DB, triggers, least-privilege role |
| Session metadata | Internal | Encrypted in-transit (TLS), limited retention scope |
| Admin credentials | Secret | Never stored in audit log — redacted pre-persistence |
| Audit DB credentials | Secret | FreePBX `astdb` config store, not in source code |
| Search/export data | Compliance-critical | RBAC-gated, rate-limited export |

## 2. STRIDE Analysis

### S — Spoofing

| Threat | Impact | Mitigation |
|--------|--------|------------|
| Attacker submits fake audit events | Pollution of compliance record | Events only created by authenticated server-side hooks, not user input |
| Session ID prediction | Impersonate another admin's audit trail | UUIDs generated by `uniqid('', true) + random_bytes(8)` — unpredictable |
| Unauthenticated auth-failure recording | Flood failure events | Rate limiting at web server layer; synthetic session IDs prefixed `authfail_` clearly separate from real sessions |

### T — Tampering

| Threat | Impact | Mitigation |
|--------|--------|------------|
| Admin modifies historical audit records | Compliance violation, cover-up | `BEFORE UPDATE` and `BEFORE DELETE` triggers on `audit_events` and `audit_sessions` reject all modifications |
| DBA modifies records directly | Bypass application-level controls | Dedicated DB account has only `INSERT + SELECT`; triggers guard even higher-privilege accounts; break-glass procedure documented |
| SQL injection to modify data | Data corruption | All queries use prepared statements; sort/filter fields validated against allowlists |
| Tampering with module code on server | Disable audit logging | Module integrity should be verified via FreePBX module signatures; server access monitoring is outside module scope |

### R — Repudiation

| Threat | Impact | Mitigation |
|--------|--------|------------|
| Admin denies performing an action | Accountability gap | Every event records `actor` (from `$_SESSION['AMP_user']->username`), `source_ip`, and timestamp |
| Admin claims timestamp was wrong | Dispute audit timing | UTC + local timezone (`Europe/Chisinau`) recorded; timestamps use `time()` — server clock authority |
| Session attribution dispute | Multi-admin confusion | Each event tied to `session_id` with explicit `login` boundary event, `actor` recorded per event |

### I — Information Disclosure

| Threat | Impact | Mitigation |
|--------|--------|------------|
| Audit log exposes passwords | Credential leak via audit search | `redactSensitiveData()` replaces password/secret/token/api_key/private_key values with `***REDACTED***` before persistence |
| Unauthorized access to audit data | Compliance data leak | RBAC check (`checkSection('auditcompliance')`) on page load and all AJAX endpoints |
| Audit DB connection credentials exposed | DB compromise | Credentials stored in FreePBX `astdb`, not in source; DSN validated for TLS |
| Export data exfiltration | Bulk data theft | Export rate-limited (10s cooldown), bounded to 5000 rows, RBAC-gated |

### D — Denial of Service

| Threat | Impact | Mitigation |
|--------|--------|------------|
| High-volume event logging overwhelms DB | Audit write failures, FreePBX slowdown | Synchronous write with error isolation (try/catch); failed writes logged but don't crash the GUI operation |
| Search query abuse | DB load spike | Pagination enforced (`max 200 rows/query`), export bounded to 5000 rows, rate limiting on export |
| Excessive auth failure logging | Storage exhaustion | Synthetic session IDs avoid session table bloat; monitoring recommended for failure event volume |

### E — Elevation of Privilege

| Threat | Impact | Mitigation |
|--------|--------|------------|
| Non-admin accesses audit module | Data exposure | `FREEPBX_IS_AUTH` guard + `checkSection()` RBAC |
| Admin escalates to modify audit records | Compliance breach | No `UPDATE/DELETE` grants + DB triggers; no admin-accessible API to modify records |
| Exploit in audit module grants broader access | System compromise | Module only reads session state and writes to audit DB; no system commands, no file access, no URL fetching from user input |

## 3. OWASP Top 10 Mapping

| OWASP | Control | Implementation |
|-------|---------|----------------|
| A01 Broken Access Control | Section-based RBAC | `checkSection('auditcompliance')` on page + AJAX |
| A02 Cryptographic Failures | TLS-enforced DB connections | `validateDsnSecurity()` rejects non-TLS DSNs; `getConfigSafe()` defaults to TLS enabled even when config store returns `false` |
| A03 Injection | Prepared statements everywhere | All `$pdo->prepare()` with bound parameters; allowlist for sort/filter columns; explicit `ESCAPE '\'` on all LIKE clauses for PostgreSQL compatibility |
| A04 Insecure Design | Append-only architecture | DB triggers, least-privilege role, no update/delete API surface |
| A05 Security Misconfiguration | Secure defaults | TLS required by default; fail-safe config retrieval via `getConfigSafe()`; fallback to local DB only if no remote DSN configured |
| A06 Vulnerable Components | FreePBX framework dependency | Module requires `framework >= 17.0.1`; no external PHP dependencies |
| A07 Auth Failures | Reliable actor attribution | Session-based username extraction; auth failure logging with IP tracking |
| A08 Software/Data Integrity | Immutable event records | DB triggers prevent modification; module signing via FreePBX packaging |
| A09 Logging Failures | Self-monitoring | `debugLog()` for internal errors; guaranteed timestamp + actor + outcome on every event |
| A10 SSRF | No outbound requests | Module never fetches URLs from user input |

## 4. Residual Risks

| Risk | Severity | Mitigation Status |
|------|----------|-------------------|
| DBA with superuser access can disable triggers | Medium | Documented break-glass procedure; recommend monitoring `ALTER TRIGGER` and `DROP TRIGGER` statements |
| Server-level compromise can modify module code | High | Out of scope for this module; recommend file integrity monitoring (AIDE/OSSEC) |
| Clock tampering affects timestamp accuracy | Low | Use NTP synchronization; audit DB server should have independent time source |
| FreePBX framework vulnerability bypasses auth | Medium | Dependent on upstream security; module adds defense-in-depth via RBAC checks |
| Modules that don't call `processHooks()` have gap in hook-based capture | Low | Covered by `doConfigPageInit` for GUI submissions; AJAX-only paths documented in coverage matrix |
